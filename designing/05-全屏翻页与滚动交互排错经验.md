# 全屏翻页 / 滚动交互 / hash 路由 通用排错经验（05）

> 对应问题：滚轮无法切换、页面直达空白、Footer 不显示、URL hash 同步等
> 适用范围：Astro + GSAP Observer 的整屏滚动站、任意"hash 驱动单页分区"的站点

## 一、整屏翻页（Full Page Scroll）的标准架构

### 1.1 DOM 结构三要素

```
body (block-size:100dvb, overflow:hidden)
  ├─ 固定层：Header 等 (position: fixed)
  └─ 分区层：
      ├─ div.snap-section#Prologue (data-section="1")
      ├─ div.snap-section#Symphony (data-section="2")
      └─ div.snap-section#Epilogue (data-section="4")
```

关键样式（**必须生效，否则全屏翻页直接崩**）：

```css
.snap-section {
  position: absolute;   /* 全部堆叠在同一坐标 */
  inset: 0;             /* 或 top:0;left:0;width:100%;height:100% */
  overflow: hidden;
}
```

**经典翻车点**：`.snap-section` 的定位样式所在的 CSS **没被引入**。此时各分区退化成普通文档流、上下排列，超出视口的被 `overflow:hidden` 裁掉 → "后面的页面完全看不到"。排查时**优先确认定位 CSS 确实被 import 了**。

### 1.2 分区控制逻辑（GSAP Observer）

```ts
import { gsap } from 'gsap'
import { Observer } from 'gsap/Observer'

let currentIndex = 0
let isAnimating = false
let sections: HTMLElement[] = []

gsap.registerPlugin(Observer)
sections = gsap.utils.toArray('.snap-section')

// 初始：全隐藏，只显示当前屏
sections.forEach((el) => gsap.set(el, { autoAlpha: 0, pointerEvents: 'none' }))
gsap.set(sections[currentIndex], { autoAlpha: 1, pointerEvents: 'auto' })

Observer.create({
  type: 'wheel,touch,pointer',
  wheelSpeed: -1,                     // ← 方向关键，见第二节
  onUp:   () => goTo(currentIndex + 1),
  onDown: () => goTo(currentIndex - 1),
  tolerance: 10,
  preventDefault: true,
})
```

## 二、GSAP Observer 滚轮方向（最容易搞反的坑）

### 2.1 语义

| wheelSpeed | 滚轮向下滚时触发 | 滚轮向上滚时触发 |
|-----------|----------------|----------------|
| `1`（默认） | `onDown` | `onUp` |
| `-1`（反转） | `onUp` | `onDown` |

### 2.2 推导"下滑 = 下一页"的正确写法

目标：**滚轮向下滚 → 下一页**。

- 用 `wheelSpeed: -1` 时，滚轮向下 → 触发 `onUp` → 所以 `onUp` 应指向 `goTo(next)`
- 用 `wheelSpeed: 1`（默认）时，滚轮向下 → 触发 `onDown` → 所以 `onDown` 应指向 `goTo(next)`

两者写法不同但效果一致。**建议统一用 `wheelSpeed: -1` + `onUp→next`**（这是旧版验证过的配置）。

**翻车表现**：方向反时，第 1 屏向下滚会执行 `goTo(0-1)` 被越界拦截 → "下滑没反应"；而向上滚却跳到下一页 → 行为完全颠倒。

### 2.3 快速判断方向

不要靠猜。**最小验证法**：在 `onUp`/`onDown` 里临时 `console.log`，滚一下看触发哪个，再决定映射。比读文档快。

## 三、URL hash 路由与 SEO（关键结论：不影响 SEO）

### 3.1 为什么 hash 对 SEO 无影响

1. **HTTP 请求不带 hash**：浏览器访问 `/studio#Epilogue`，发给服务器的只有 `/studio`。服务端（SSR）拿不到 hash。
2. **爬虫不单独收录 hash**：`#xxx` 被视为同一页面的**内部锚点**，不会当独立 URL、不制造重复内容、不分摊权重。
3. **canonical / og:url 保持干净**：只要它们用服务端 URL（`Astro.url`），就永远是 `https://domain/path`，不含 hash。

### 3.2 工程上的正确姿势

- **canonical / og:url**：始终用不含 hash 的 URL
- **sitemap**：只列干净的路径 URL（如 `/studio`），不要列 `#Prologue` 之类
- **hash 只用于**：定位初始分区、前进后退、分享时记住位置

## 四、hash 同步的最佳实践

### 4.1 三个功能点（缺一不可）

1. **直达**：加载时读 `location.hash` → 定位到对应分区
2. **同步**：翻页后用 `history.replaceState` 把当前分区写进地址栏（不产生历史记录、不触发 `hashchange` 回环）
3. **响应**：监听 `hashchange` → 支持浏览器前进/后退

### 4.2 关键代码模式

```ts
// 1. 读 hash → 分区下标
function sectionIndexFromHash(): number {
  const id = window.location.hash.replace('#', '')
  if (!id) return 0
  const idx = sections.findIndex((el) => el.id === id)
  return idx >= 0 ? idx : 0
}

// 2. 写 hash（replaceState：不触发 hashchange，无回环）
function syncHash(index: number) {
  const id = sections[index]?.id
  if (id) window.history.replaceState(null, '', `#${id}`)
}

// 3. 响应前进/后退
window.addEventListener('hashchange', () => goTo(sectionIndexFromHash()))

// 4. 初始化时同步一次：/studio → /studio#Prologue
syncHash(currentIndex)
```

### 4.3 防回环的守卫

```ts
function goTo(index: number) {
  // index === currentIndex 必须拦截，否则 hashchange 会自我触发动画重播
  if (isAnimating || index < 0 || index >= sections.length || index === currentIndex) return
}
```

### 4.4 要点记忆

- **`replaceState` 不触发 `hashchange`**；`location.hash = x` 或 `pushState` 会触发 → 用前者做同步就不会循环
- 前进/后退（`hashchange`）与滚动（Observer）都汇聚到同一个 `goTo`，方向与状态统一由 `currentIndex` 管理

## 五、分区切换动画（滑动 vs 淡入淡出）

### 5.1 两种常见实现

| 效果 | 实现 | 时长/缓动 |
|------|------|----------|
| 淡入淡出 + 缩放 | `opacity` + `scale` | 0.6s `power2` |
| **上下滑动**（推荐） | `yPercent` | 1.2s `power4.inOut` |

### 5.2 滑动翻页模板

```ts
function goTo(index: number) {
  if (isAnimating || index < 0 || index >= sections.length || index === currentIndex) return
  isAnimating = true

  const direction = index > currentIndex ? 1 : -1
  const outgoing = sections[currentIndex]
  const incoming = sections[index]

  const tl = gsap.timeline({
    onComplete: () => {
      gsap.set(outgoing, { autoAlpha: 0, zIndex: 0, pointerEvents: 'none' })
      gsap.set(incoming, { yPercent: 0, zIndex: 1, pointerEvents: 'auto' })
      isAnimating = false
      currentIndex = index
      syncHash(index)
    },
    defaults: { duration: 1.2, ease: 'power4.inOut' },
  })

  gsap.set(incoming, { yPercent: 100 * direction, autoAlpha: 1, zIndex: 2, pointerEvents: 'none' })
  tl.to(outgoing, { yPercent: -100 * direction })  // 旧屏滑出
  tl.to(incoming, { yPercent: 0 }, '<')             // 新屏滑入（'<' 表示同时开始）
}
```

### 5.3 首屏入场动画

- 只在 `currentIndex === 0`（首页）播放
- 用 `tl.from('.logo, .title-text', {...})` 等对**初始隐藏的静态元素**做入场
- 直达其他分区（如 `#Epilogue`）时跳过入场，避免"直达第二页却播第一页动画"

## 六、排错方法论（本次最值钱的部分）

### 6.1 二分定位法：是"内容没渲染"还是"内容被藏了"

症状："某屏空白 / 看不到"。

1. **先查 DOM**：`curl 页面` 或看元素，确认内容**在不在 HTML 里**。在 → 是 CSS/JS 可见性问题；不在 → 是渲染/路由问题。
2. **临时禁用动画层**：把隐藏逻辑（`autoAlpha: 0`）临时改成全部可见，看内容是否出现。
   - 出现了 → 动画/显隐逻辑的 bug
   - 还不出现 → 是布局/定位/引入问题
3. **检查"定位 CSS 是否引入"**：整屏翻页站点，`position:absolute` 的 `.snap-section` 是最先该怀疑的点。**漏 import 一个 CSS 就能让所有后续分区"消失"**。

### 6.2 不要"打补丁式"排查

前几轮我先怀疑颜色、opacity、zIndex，各种加补丁都无效——因为**根因是 CSS 没引入**，属于结构性缺失。经验：

- 症状反复出现且"加什么都无效"时，**回头查最基础的假设**（这个 class 的样式到底加载了没）
- 用 `curl` 看页面实际引用的 CSS 列表，比对代码里 import 了什么、漏了什么

### 6.3 区分几个易混概念

| 现象 | 可能的根因 |
|------|-----------|
| 后面的页面完全看不到 | `.snap-section` 定位 CSS 未引入（最优先查） |
| 能切换但新屏空白 | 动画终态没锁定 / 新屏内容本身问题 |
| 能切到但方向反 | `wheelSpeed` 或 `onUp/onDown` 映射反了 |
| `#xxx` 直达空白 | 初始状态没读 hash，写死显示第一个分区 |
| 前进/后退无效 | 没监听 `hashchange` |

## 七、Astro 项目里 CSS 的常见坑（通用）

1. **`<style>` 默认 scoped**：Astro 会给选择器加 `data-astro-cid-*`。跨组件/全局样式要用 `:global(...)` 或在全局 CSS 文件定义。
2. **全局 CSS 必须显式 import**：`src/css/nonGlobal/*.css` 不会自动加载，要在 `.astro` 的 frontmatter 里 `import '/src/css/nonGlobal/xxx.css'`。**漏 import 是最隐蔽的 bug**（build 不报错，样式悄悄缺失）。
3. **CSS 变量分层**：`:root`/`.dark` 上定义的变量全局生效；组件内直接 `var(--xxx)` 即可，无需 import（但**变量定义所在文件要引入**）。
4. **逻辑属性 vs 物理属性**：竖排（`writing-mode: vertical-rl`）下 `padding-inline` 对应垂直方向、`padding-block` 对应水平方向——搞反会导致"左右空隙不对称"。
