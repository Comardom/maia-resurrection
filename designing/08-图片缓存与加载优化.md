# 图片缓存与加载优化（08）

> 记录 2026-08「时间线图片加载慢」问题的**完整诊断与解决方案**：三层缓存链路（Nginx 静态缓存 → Cloudflare CDN → 浏览器缓存）+ 播放器预加载。
> 依据：`AnsibleProjects/alma/playbooks/manage_webpage/templates/nginx-ssr.conf.j2`、`playbook-mkdir_and_chmod.yaml`、`src/components/studio/timelinePlayerScript.ts`、Cloudflare 面板实测数据。

## 一、问题与诊断

### 1.1 现象

- 服务器带宽 20Mbps，用户反馈时间线每切换一张图片要卡 1~2 秒。
- 初步怀疑是图片太大。

### 1.2 实测结论（关键转折）

用 `curl` 分别测小图（27KB）与大图（200KB）的实际耗时：

```
199KB 图片:  TTFB 1.58s  total 2.90s
27KB  图片:  TTFB 1.69s  total 2.22s
```

- 20Mbps 理论下载速度 ≈ 2.5MB/s，200KB 图片下载只需约 **0.08s**。
- 连 27KB 的小图也要 2 秒，说明瓶颈**不在体积，在「下载开始前」的等待（TTFB）**。
- 压缩图片只能缩短实际传输时间，**解决不了 TTFB 延迟**。方向错了。

### 1.3 真正的原因（两个）

1. **Nginx 把所有请求都反代给 Node**：包括 `/studio-history/*.webp`，图片每次都要经 Astro/Node 处理，且没有任何静态缓存规则。
2. **播放器不预加载**：切换时才设置 `stage.src`，每张图都暴露一次完整 TTFB。

## 二、解决方案：三层缓存链路

```
浏览器 ──→ Cloudflare 边缘节点 ──→ 我们的 Nginx ──→ Node(Astro)
  ↑浏览器缓存30天   ↑CDN缓存30天       ↑静态文件直读，不进 Node
```

### 2.1 第一层：Nginx 静态缓存（解决「回源进 Node」）

在 `nginx-ssr.conf.j2` 中，**仅对 Maia** 增加静态目录规则：

```nginx
{% if item.name == 'maia-resurrection' %}
    location ^~ /studio-history/ {
        root /var/www/maia-resurrection/client;
        try_files $uri =404;
        expires 30d;
        log_not_found off;
    }
{% endif %}
```

- `expires 30d` 生成响应头 `cache-control: max-age=2592000`。
- 图片由 Nginx 直接从磁盘读取，不再进 Node。
- **必须用 `{% if item.name == 'maia-resurrection' %}` 包裹**：该 playbook 会遍历 `sites`（含 erp），若不加条件，ERP 域名也会被套上指向 Maia 目录的静态规则。
- 文件实际路径：`/var/www/maia-resurrection/client/studio-history/`（Astro build 后 `public/` 内容进 `dist/client/`）。

### 2.2 第二层：Cloudflare CDN

- Cloudflare 读取源站 `cache-control: max-age=2592000`，首次 `MISS` 回源后存入边缘节点。
- 之后请求 `HIT`，由边缘节点直接返回，不再回源。
- 实测对比：

| 项目 | 改前 | 改后 |
|------|------|------|
| cache-control | `max-age=14400`（CF 默认 4h） | `max-age=2592000`（源站 30 天） |
| cf-cache-status | `REVALIDATED` / `MISS` | `HIT` |
| 响应来源 | 每次回源 | 边缘节点（`cf-ray: ...-SEA`） |

### 2.3 第三层：浏览器缓存

- 同样的 `max-age=2592000`，用户本地浏览器缓存 30 天，重复访问连 CDN 都不打。

## 三、播放器预加载（消除切换等待）

在 `src/components/studio/timelinePlayerScript.ts` 中：

```ts
const imageCache = new Set<string>()

function preloadImage(src: string) {
  if (!src || imageCache.has(src)) return
  imageCache.add(src)
  const img = new Image()
  img.src = src
}

function preloadTimelineImages() {
  timelineEvents.forEach((ev) => {
    if (ev.image) {
      preloadImage(ev.image.src)
      if (ev.image.dark) preloadImage(ev.image.dark)
    }
  })
}
```

触发时机：**进入 Timeline 区块时**（`section:change` 事件 `id === 'Timeline'` 分支）：

```ts
if (id === 'Timeline') {
  preloadTimelineImages()
  inView = true
  ...
}
```

要点：

- 为什么不在页面加载时预载：studio 是全屏翻页，Timeline 不在首屏。页面加载就预载会占用 20Mbps 带宽拖慢首屏；进入该区块后再后台预载（总量约 1.9M）即可。
- `imageCache` 用 `Set` 去重，重复进入不会重复请求。
- `new Image()` 只赋值 `src` 即触发浏览器加载，不插入 DOM。
- 切换时 `setStageImage` 的 200ms 淡入照旧，但图片已在浏览器缓存，`stage.src` 赋值立即生效。

## 四、Ansible Playbook 修复（部署链路）

本次踩到的两个坑，均已修复：

1. **`playbook-mkdir_and_chmod.yaml`**：`upload package.json` 与 `install production deps` 两任务加了 `when: item.name == 'maia-resurrection'`。原 playbook 会遍历 `sites` 含 erp，但 erp 无 `pkg` 字段（inventory 里只有 `name/domain/src/cert_base`），`item.pkg` 为空导致报错；erp 目录也没有 package.json 供 `pnpm install`。
2. **pnpm 不在 `normalMe` 的 PATH**：`cmd` 改为全路径 `/usr/local/bin/pnpm install --prod`（与 maia playbook 中 `/usr/local/bin/pm2` 全路径写法一致）。

部署顺序：

```bash
sh run.sh manage_webpage/playbook-mkdir_and_chmod.yaml   # 上传解压新包 + 装依赖
sh run.sh manage_webpage/playbook-maia-https_and_nginx_conf.yaml  # nginx -t + reload + pm2 重启
```

## 五、Cloudflare 面板设置建议

### 5.1 缓存级别：选「标准」

- 本站图片 URL 无查询参数，三种模式今天表现一样。
- Astro 资源是**内容哈希文件名**（`headerScript.DLvVWwfG.js`），不靠 `?v=` 破缓存。
- 「忽略查询字符串」会在未来给图加 `?v=` 时把参数全忽略、缓存到旧图；「没有查询字符串」会把带参数 URL 直接不缓存。「标准」对带不带参数都正确，最省心。

### 5.2 浏览器缓存 TTL：选「尊重源站头」或 30 天

- 实测当前源站 `expires 30d` 的头已被透传（响应里是 `max-age=2592000`），说明该设置未在覆盖源站头。
- 最干净做法：选「尊重现有头（Respect existing headers）」，让 Nginx 成为唯一控制点；无此选项则选 30 天与 Nginx 对齐。
- **坑**：浏览器缓存 30 天后，若换同名但更小的图重新部署，用户会继续用旧图最多 30 天。CF purge 只能清 CDN 层，清不掉浏览器本地缓存。要用户立刻看到新图，只能改文件名（如加日期/哈希），或临时调低 TTL 过渡。

## 七、大陆访问现状与可选方向

实测对比（中国大陆网络环境）：

```
                RTT       TTFB        total
直连源站(腾讯云)  117ms     0.50s       2.72s
走Cloudflare     ——        1.64s       3.19s
```

- 源站本身延迟只有 117ms，问题全在 Cloudflare 把流量绕到**西雅图（SEA）边缘节点**——免费版不能选香港/大陆节点。
- Vercel 无大陆节点，同样不行。
- 可选方向（按代价排序）：
  1. **维持现状**：每个用户每张图只付一次首访 1.6s TTFB，之后 30 天全走浏览器缓存，秒开。
  2. **直连源站**：DNS 指 `43.133.61.7`，换 Let's Encrypt 公共证书（现用 Cloudflare origin 证书浏览器不信任），TTFB 预计 0.5s，代价是失去 CF 隐藏源站/DDoS 保护。
  3. **腾讯云 CDN（EdgeOne）**：亚太边缘节点，大陆访问比 CF 西雅图快；大陆节点仍需 ICP 备案。
  4. **ICP 备案 + 阿里云/腾讯云大陆 CDN**：终极方案，延迟最低，但要走真实世界备案流程。
