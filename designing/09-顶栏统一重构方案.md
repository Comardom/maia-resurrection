# 09-顶栏统一重构方案（Header 组件化）

> 状态：方案定稿，待实施
> 目标版本：基于 `0.5.2`（HEAD）

## 一、背景与目标

当前顶栏在 `studio` 与 `office` 两套代码里**分裂重复**：

- `src/components/studio/Header.astro`（studio 系 6 页共用）
- `src/components/office/OfficeMasthead.astro`（office 页专用）
- 两者的应用中心（菜单/磁贴/关闭条/背板）、QQ 神灯、主题钮、图标 CSS 约 90% 逐字重复
- 脚本三份重复：`studio/headerScript.ts`、`office/officeAppMenuScript.ts`、`office/officeHeaderScript.ts`

目标：

1. 统一成一个 `Header.astro` 组件，桌面端用 `canMove` prop 选变体，移动端全站一致
2. 桌面端 studio/office 仅存 3 个差异，全部收敛为 CSS 变量
3. 应用中心菜单内部**横向滚动**（桌面/移动通用），菜单外页面滚动正常
4. 样式按 tasKapsule `globalCSS` 模式组织（变量集中、全称、少缩写）
5. 脚本统一一份

## 二、核心决策

### 2.1 统一基准

一切参数**全面向 studio 版本对齐**，摒弃 office 的错误数据。移动端两页天然一致。

### 2.2 桌面端仅存的 3 个差异

| 差异 | studio | office |
|---|---|---|
| 是否 fixed | fixed（固定） | relative（随页面滑动） |
| 是否两个 breath 动画 | 有 | 无 |
| 是否显示主题切换按钮 | 显示 | 隐藏 |

其余数值（顶栏高、内边距、logo 高）**统一一份**，不再分裂。

### 2.3 canMove 语义

- `canMove` 表示「顶栏会随页面上下滑动（不固定）」= **office 变体**
- 页面写法：
  - studio 系 6 页：`<Header />`（不传）→ fixed + 呼吸 + 主题钮
  - office：`<Header canMove />` → relative + 无动画 + 无主题钮

### 2.4 CSS 变量归属

- `:root` 默认 = **studio 基准**（`--header-position: fixed`、`--header-breathe` 有、`--header-show-theme-toggle: flex`）
- `header[data-can-move]` 覆盖 = **office**（`relative`、`none`、`none`）

### 2.5 移动端菜单高度

- 桌面：`30dvb`
- 移动：`40dvb`（由原 75dvb 调整）

### 2.6 应用中心滚动 scoped（横向，通用）

- `.app-menu-tiles`：`display: flex` 单行横排 + `overflow-x: auto` + 每 tile `flex: 0 0 auto`
- 不加 scroll-snap（保持简单）
- 菜单外页面滚动完全正常，**不再锁 body**

### 2.7 lockScroll

`initAppMenu({ lockScroll })` 参数**保留但暂不引用**（默认不锁）。以后需要再开。

## 三、目录结构

```
src/components/header/
├── Header.astro        # 主体：<header data-can-move?> + 三组 + AppCenter + QqPopup
├── LogoUndName.astro   # logo + 站名（原 Brand，改名利于非英语母语者理解）
├── ThemeToggle.astro   # 主题切换按钮
├── AppCenter.astro     # 应用中心（菜单 + 磁贴 + 关闭条 + 背板）
├── QqPopup.astro       # QQ 神灯
├── header.css          # ①变量 ②共享规则 ③变体
└── headerScript.ts     # 统一脚本
```

## 四、CSS 组织（header.css，三段式）

模仿 tasKapsule `frontend/src/globalCSS` 的变量集中管理模式，**变量全称、少缩写**（不用 `hdr` 这类缩写，统一用 `--header-*` 前缀）。

### ① 变量段（`:root` + `[data-can-move]` 覆盖）

```css
:root {
    /* studio 基准（默认） */
    --header-position:          fixed;
    --header-breathe:           none;      /* 由变体填入动画 */
    --header-show-theme-toggle: flex;
    --header-top-height:        7svb;      /* 桌面顶栏高 */
    --header-top-padding-inline: 2rem;
    --header-logo-height:       3rem;
}

header[data-can-move] {
    /* office 变体 */
    --header-position:          relative;
    --header-breathe:           none;
    --header-show-theme-toggle: none;
    --header-top-height:        4.5rem;
    --header-top-padding-inline: 2rem;
    --header-logo-height:       3rem;
}
```

> 注：以上变量名与数值为示意，实施时以 studio 0.5.2 实际值核对为准（`7svb`、`2rem`、`3rem` 等）。

### ② 共享规则段

`.top-bar`、`.left-group/.center-group/.right-group`、logo、主题钮、`.app-menu`、`.app-menu-tiles`、`.tile`、`.qq-popup` 等规则，**只引用变量**，不散落写死值。

### ③ 变体段

`header[data-can-move]` 只做变量赋值（几行），不重复写样式规则。

## 五、组件拆分

| 组件 | 内容 | 来源 |
|---|---|---|
| `Header.astro` | `<header data-can-move>` + 三组 + 引入子组件 | 原 `Header.astro` + `OfficeMasthead.astro` 外壳 |
| `LogoUndName.astro` | logo(light/dark) + 站名 | 原 `Brand` 抽取，改名 |
| `ThemeToggle.astro` | luna/solar 主题钮 | 抽取 |
| `AppCenter.astro` | 菜单 + 磁贴 + 关闭条 + 背板（含 `#app-menu` 等） | 抽取，须留在 `<header>` 内层叠上下文 |
| `QqPopup.astro` | QQ 神灯（5 切片） | 抽取，须留在 `<header>` 内层叠上下文 |
| `headerScript.ts` | `initThemeToggle` + `initAppMenu({lockScroll})` + `closeAppMenu` | 合并 studio + office 两份 |

> 关键：`AppCenter` 与 `QqPopup` 必须仍渲染在 `<header>` 内部（神灯 z-index 1005 / 背板 1001 / 菜单 1002 依赖 header 层叠上下文与 app-menu 的 transform 包含块）。

## 六、脚本统一

- 只留一份 `src/components/header/headerScript.ts`：
  - `initThemeToggle`：统一为 `data-theme-control` 机制（含 `colorScheme`、`theme:change` 事件）
  - `initAppMenu({ lockScroll })`：`lockScroll` 保留、暂不引用
  - `closeAppMenu`：程序化关闭（供 `pageAnimator.ts` 翻页用）
- 删除：`studio/headerScript.ts`、`office/officeAppMenuScript.ts`
- `office/officeHeaderScript.ts` 拆解：
  - scrollspy 部分 → `src/components/office/sectionNavScript.ts`（仅 `OfficeSectionNav.astro` 用）
  - 主题控件 → 并入 `headerScript.ts`
- `utils/qqPopupGenie.ts` 保留（作用于当前页唯一一份神灯 DOM）

## 七、SectionNav 与 Header 的关系（独立）

- **SectionNav 不是 Header 的一部分**，是页面里与 Header 并列的独立组件
- 互不嵌套、互不引用逻辑
- 仅**共用 2 个高度变量**（从 `:root` 读）：
  - `--office-masthead-height`
  - `--office-section-nav-height`
- section-nav 样式**内联进 `OfficeSectionNav.astro`**，不混入 header.css

## 十、验证（不部署）

1. `pnpm run build` + `pnpm run typecheck`
2. CDP 桌面对拍：
   - studio（不传）：`fixed` + 呼吸动画 + 主题钮可见 + 菜单开/关正常
   - office（canMove）：`relative` + 无动画 + 主题钮隐藏 + scrollspy 正常
3. CDP 移动端两页一致性对拍（顶栏高、logo、按钮位置、`40dvb`、横向滚动）
4. 应用中心横向滚动实测（桌面 + 移动）
5. 6 个 studio 页冒烟（variant 正确、tile/menu 存在）

## 十一、风险与注意

- 神灯 / 背板 / 菜单 z-index 依赖 header 层叠上下文 → `AppCenter`、`QqPopup` 必须留在 `<header>` 内
- `--office-masthead-height` / `--office-section-nav-height` 被 `office.astro` 的 padding 与 section-nav 定位引用 → 需在 header.css 或 `:root` 保留定义
- 删除 `officeHeader.css` 前先确认 section-nav 规则迁移完整
- 菜单改横向滚动会改变现有「网格自动换行」布局 → 需确认接受
