# 字体子集化与按需加载架构

> 当前实现说明
> 范围：Header 全站独立子集；studio 分页内容按小页拆分；Timeline 不使用自定义字体

## 1. 目标

本项目的字体加载分为两类：

```text
共享区域：Header
分页区域：studio 的 Prologue、Symphony、Timeline、Epilogue
```

目标是：

- 所有页面的 Header 站名使用同一份独立 Huiwen 子集
- Header 的其他文字使用系统字体
- studio 的每个分页区域只使用自己的字体子集
- 每种字体只包含它实际负责显示的文字
- 首次进入 studio 时先加载当前页字体
- 当前页稳定后，其他分页字体全并行后台预取
- 直接通过 hash 进入某一页时，优先加载该页字体
- Timeline 完全使用系统字体
- Timeline 图片继续使用原有异步预载逻辑
- 字体文件使用内容 hash 命名，并使用长期缓存

## 2. 最终字体归属

字体归属以页面现有 CSS 和 JavaScript 的实际使用点为准。子集化只拆分资源，不重新设计字体。

### 2.1 Header

Header 是所有页面共用的组件：

```text
src/components/header/Header.astro
src/components/header/LogoUndName.astro
src/components/header/AppCenter.astro
src/components/header/ThemeToggle.astro
src/components/header/QqPopup.astro
src/components/header/header.css
```

当前要求：

```text
站名“河南大学网站工作室” → Huiwen-HKHei-Header
Header 其他文字           → 系统字体
```

Header 独立子集只包含站名，不包含：

```text
应用中心
考试系统
管理系统
QQ迎新群
打开应用中心
关闭应用中心
切换主题
```

这些文字由 Header 根节点的系统字体规则处理。

### 2.2 Prologue

Prologue 的标题动画有四种状态：

```text
PMingLiU-TW       → “河南大学网站工作室”首态和诗歌
Unifont           → “河南大学网站工作室”第二态
PangMenZhengDao   → “河南大学网站工作室”第三态
cwTeXMing         → “河南大學網站工作室”第四态
```

当前实现使用以下独立 family：

```text
PMingLiU-TW-Prologue
Unifont-Prologue
PangMenZhengDao-Prologue
cwTeXMing-Prologue
```

`cwTeXMing-Prologue` 不再 fallback 到 `PMingLiU-TW-Prologue`。

### 2.3 Symphony

Symphony 的字体分配固定如下：

```text
部门名称    → Huiwen-HKHei
部门简介    → PMingLiU-TW
Let's Rock! → PangMenZhengDao
```

对应独立 family：

```text
Huiwen-HKHei-Symphony
PMingLiU-TW-Symphony
PangMenZhengDao-Symphony
```

游戏弹窗标题当前不自动套用 PangMenZhengDao。只有明确使用 PangMenZhengDao 的 `Let's Rock!` 进入该子集。

### 2.4 Timeline

Timeline 没有任何自定义字体使用点。

因此：

- 不生成 Timeline 字体子集
- 不生成 `Timeline-*.txt`
- 不生成 `Huiwen-HKHei-Timeline`
- 不加入字体 manifest
- 不参与字体预取
- Timeline 的标题、描述、年份和控制文字使用系统字体
- Timeline 图片逻辑不因字体架构改变

### 2.5 Epilogue

Epilogue 的字体分配保持现有使用关系：

```text
Footer 链接              → Huiwen-HKHei
版权、制作信息、统计文字 → PMingLiU-TW
```

对应独立 family：

```text
Huiwen-HKHei-Epilogue
PMingLiU-TW-Epilogue
```

这些规则在桌面端和移动端都有效。移动端媒体查询只负责尺寸、方向和布局，不负责决定字体是否存在。

### 3.3 字表

## 4. 字体文件命名与版本

字体文件使用生成后的 woff2 内容计算 hash：

```text
<font>-<section>-<hash8>.woff2
```

示例：

```text
hkhei-header-c7543e82.woff2
pmzd-prologue-a925e938.woff2
hkhei-symphony-e41efa8b.woff2
pmingliu-epilogue-3d356e27.woff2
```

hash 的来源是 woff2 二进制内容，而不是：

```text
当前日期
Git 版本号
package.json 版本号
手工输入的 v2
```

规则：

```text
字体内容不变 → hash 不变 → 浏览器复用缓存
字体内容变化 → hash 变化 → 浏览器自动拉取新文件
```

这样不需要手动维护日期后缀或版本号。

## 5. 生成器的核心原则

错误方式：

```text
Prologue 全部文字
    → PMingLiU 子集
    → Unifont 子集
    → PangMenZhengDao 子集
    → cwTeXMing 子集
```

正确方式：

```text
实际字体使用点
    → 该使用点实际显示的文字
    → 对应字体子集
```

生成器的配置结构应当表达这种关系：

```js
const sections = {
    Prologue: {
        fonts: {
            pmingliu: [
                '河南大学网站工作室',
                'Prologue 中实际使用 PMingLiU 的诗歌文字',
            ],
            unifont: ['河南大学网站工作室'],
            pmzd: ['河南大学网站工作室'],
            cwtex: ['河南大學網站工作室'],
        },
    },
    Symphony: {
        fonts: {
            hkhei: ['实际显示的部门名称'],
            pmingliu: ['实际显示的部门简介'],
            pmzd: ["Let's Rock!"],
        },
    },
}
```

不能把 `.astro` 文件整体读取后作为字表，因为源码中包含：

- CSS 属性
- JavaScript 注释
- 不一定显示的备用字符串
- 组件结构文本
- 与字体使用无关的代码

## 6. CSS 使用规则

### 6.1 Header

Header 根节点使用系统字体：

```css
header[data-header] {
    font-family:
        -apple-system,
        BlinkMacSystemFont,
        "Segoe UI",
        "PingFang SC",
        "Microsoft YaHei",
        "Noto Sans CJK SC",
        sans-serif;
}
```

只有站名单独使用 Header Huiwen：

```css
.title-text {
    font-family:
        'Huiwen-HKHei-Header',
        -apple-system,
        BlinkMacSystemFont,
        "Segoe UI",
        "PingFang SC",
        "Microsoft YaHei",
        "Noto Sans CJK SC",
        sans-serif;
}
```

所有页面统一使用这个 alias，不再用 `studio-page` 做覆盖：

```text
studio      → Huiwen-HKHei-Header
office      → Huiwen-HKHei-Header
web         → Huiwen-HKHei-Header
design      → Huiwen-HKHei-Header
maintenance → Huiwen-HKHei-Header
newMedia    → Huiwen-HKHei-Header
video       → Huiwen-HKHei-Header
```

### 6.2 studio section

section 字体只在当前 section 的 active 或 entering 状态下使用：

```css
#Symphony.is-active .band-name,
#Symphony.is-entering .band-name {
    font-family:
        'Huiwen-HKHei-Symphony',
        -apple-system,
        BlinkMacSystemFont,
        "Segoe UI",
        "PingFang SC",
        "Microsoft YaHei",
        sans-serif;
}
```

`is-active` 表示当前稳定页面。

`is-entering` 表示正在进入、已经开始显示的页面。

section 间不互相作为 Web Font fallback。缺字时只回退到系统字体，不回退到另一个 section 的 Web Font。

## 7. 分页状态与字体时序

### 7.1 初始化

`src/utils/pageAnimator.ts` 初始化时：

```text
读取 URL hash
→ 确定 currentIndex
→ 设置当前 section.is-active
→ 设置当前 section 可见
→ 更新 hash
→ 广播 section:change
→ 使用当前 section 的 manifest 调用 document.fonts.load
→ 安排其他 section 的后台预取
```

直接进入：

```text
/studio
    → Prologue

/studio#Prologue
    → Prologue

/studio#Symphony
    → Symphony

/studio#Epilogue
    → Epilogue
```

Timeline 可以直接进入，但它没有自定义字体准备步骤。

### 7.2 翻页开始

翻页开始时不能立即移除旧页面的 `is-active`，否则旧页面仍在屏幕上，却已经失去自定义字体，会产生明显闪烁。

正确过程：

```text
记录 outgoing 和 incoming
→ incoming 添加 is-entering
→ outgoing 继续保留 is-active
→ 更新 currentIndex、hash、section:change
→ 准备 incoming 字体
→ 开始 GSAP 过渡
```

过渡期间的状态示例：

```text
Prologue: is-active=true
Symphony: is-entering=true
```

### 7.3 翻页完成

```text
旧页面隐藏
→ 旧页面移除 is-active
→ incoming 移除 is-entering
→ incoming 添加 is-active
→ 清理动画状态
```

因此整个过渡期间：

- 旧页面不会突然变成系统字体
- 新页面可以提前开始字体加载
- 字体加载不会阻塞翻页动画

不应等待：

```ts
await document.fonts.ready
```

字体加载不应成为翻页动作的阻塞条件。

## 8. 当前页字体准备

当前页字体通过已注册的 alias 调用 Font Loading API：

```ts
for (const { alias, sample } of studioFontManifest[id]) {
    document.fonts.load(`1em "${alias}"`, sample)
}
```

这里使用每个字体自己的 sample，而不是整个 section 的混合文本。

原因：

- 让浏览器加载正确的 alias
- 不让无关文字参与字体匹配
- 不依赖 preload 是否已经完成
- 避免把 `new FontFace` 与 CSS @font-face 注册成两套来源

CSS `@font-face` 仍然是字体注册的唯一来源；`document.fonts.load` 只负责提前触发已注册字体的加载。

## 9. 后台全并行预取

文件：

```text
src/utils/studioFontPrefetch.ts
```

执行规则：

1. 只在 studio 页面运行。
2. 当前 section 字体不由后台预取负责。
3. Header 不作为 section 处理。
4. Timeline 不在 manifest，因此不会预取字体。
5. 其余 section 的字体一次性全并行插入 preload。
6. 使用 `fetchpriority="low"`，避免抢占当前页资源。
7. 使用 `crossorigin="anonymous"`。
8. 使用 URL 去重。
9. `navigator.connection.saveData` 开启时跳过后台预取。
10. 使用 `requestIdleCallback`，不支持时使用 timeout fallback。

预取链接形式：

```html
<link
    rel="preload"
    as="font"
    type="font/woff2"
    crossorigin
    fetchpriority="low"
    href="/font/hkhei-symphony-<hash>.woff2"
>
```

预取只负责提前取得资源，不负责注册 CSS family，也不替代 `@font-face`。

## 11. 缓存

字体文件使用 hash 文件名后，可以使用长期 immutable 缓存：

```nginx
location ^~ /font/ {
    root /var/www/maia-resurrection/client;
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable";
    log_not_found off;
}
```

这条规则位于：

```text
/home/comardom/AnsibleProjects/alma/playbooks/manage_webpage/templates/nginx-ssr.conf.j2
```

部署时由现有部署脚本和 playbook 生效。当前不自动执行线上部署。

studio 不应继续使用：

```text

```

Header 应使用：

```text

```

### 12.2 目前不能全局删除的旧流程

以下内容暂时不能直接删除：

```text
src/css/fonts.css
font/pmingliu-words.txt
font/hkhei-words.txt
font/pangmenzhengdao-words.txt

```

原因是其他页面正文仍可能使用旧的全局字体流程。

删除它们的前提是：

```text
全仓库不再引用旧 family
全仓库不再 import fonts.css
全仓库不再引用旧 subset URL
所有页面已有明确的新字体或系统字体方案
构建产物中不再出现旧字体 URL
```

### 12.3 Header 相关旧流程

Header 的旧 family 引用：

```css

```

应由 Header 独立 alias 替代：

```css

```

Header 不应使用 `.studio-page` 进行特殊覆盖。

Header 也不应放进 studio section manifest。
