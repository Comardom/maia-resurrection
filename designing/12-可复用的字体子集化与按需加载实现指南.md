# 可复用的字体子集化与按需加载实现指南

> 用途：面向其他项目复用的架构与代码说明
> 本文不依赖某一个具体项目，可以作为实现字体按区域子集化和延迟加载时的技术模板

## 1. 详细需求

### 1.1 资源需求

一个页面可能包含多个视觉区域，每个区域使用不同字体，或者使用同一原始字体的不同文字集合。

需要实现：

- 每个字体使用点拥有独立的文字集合
- 每个文字集合生成独立的 woff2 子集
- 同一原始字体在不同区域使用不同的 CSS family alias
- 字体文件使用内容 hash 命名
- 生成 CSS 和 manifest，避免手工填写 hash 文件名
- Header、导航等共享区域可以拥有自己的独立子集
- 不属于字体使用点的代码、注释、备用文案不能进入字表

### 1.2 加载需求

对分页页面：

```text
进入当前页面
→ 当前页面使用的字体先加载
→ 当前页面稳定后，其他页面字体后台全并行预取
```

如果通过 URL 直接进入某个分页区域：

```text
读取 URL 状态
→ 当前区域优先加载自己的字体
→ 其他区域字体后台预取
```

翻页过程中：

- 旧页面在离开动画结束前不能失去自己的字体
- 新页面可以在进入动画期间开始准备字体
- 字体加载不能阻塞翻页动画
- 字体加载失败时必须有系统字体 fallback

### 1.3 共享区域需求

共享 Header 与分页 section 不属于同一个加载单位：

```text
Header 字体 → Header 自己加载
分页字体    → 分页状态管理器加载
```

不能把 Header 当成某一个分页 section 放入分页 manifest。

### 1.4 设计约束

- 不改变已有字体设计，只改变资源拆分和加载方式
- 不根据主观判断重新分配文字字体
- 字体归属必须来自已有 CSS、JavaScript 或设计确认
- 不能把一个区域的全部文字复制到该区域的所有字体中
- 应优先保证当前页可用，再考虑后台预取

## 2. 核心概念

### 2.1 三种不同粒度

需要区分：

```text
原始字体文件
    → 一个 TTF，例如 Huiwen.ttf

字体使用点
    → 某个选择器或 JS 实际使用 Huiwen 的地方

加载区域
    → Header、Prologue、Symphony 等逻辑区域
```

子集生成的最小合理单位是：

```text
字体使用点的文字集合
```

加载和预取的逻辑单位可以是：

```text
加载区域
```

二者不能混为一谈。

### 2.2 字体 alias

同一个原始字体在不同区域生成不同文件时，不能全部继续使用同一个 CSS family：

```css
/* 不推荐 */
@font-face { font-family: 'Huiwen'; src: url('/font/header.woff2'); }
@font-face { font-family: 'Huiwen'; src: url('/font/timeline.woff2'); }
```

推荐使用独立 alias：

```css
@font-face { font-family: 'Huiwen-Header'; src: url('/font/header.woff2'); }
@font-face { font-family: 'Huiwen-Timeline'; src: url('/font/timeline.woff2'); }
```

这样可以明确：

- 哪个元素使用哪个子集
- 哪个文件应该被预取
- 哪个区域缺字
- 哪个区域发生了字体请求

## 3. 推荐目录结构

```text
project/
├── scripts/
│   └── generate-section-fonts.mjs
├── font/
│   ├── SourceFontA.ttf
│   ├── SourceFontB.ttf
│   └── sections/
│       ├── Header-fontA.txt
│       ├── SectionA-fontA.txt
│       └── SectionB-fontB.txt
├── public/font/
│   ├── fonta-header-<hash>.woff2
│   ├── fonta-section-a-<hash>.woff2
│   └── fontb-section-b-<hash>.woff2
├── src/css/
│   ├── generated-header-font.css
│   └── generated-section-fonts.css
├── src/data/generated/
│   └── sectionFontManifest.ts
└── src/utils/
    └── sectionFontPrefetch.ts
```

原始 TTF 不应放在公开静态目录。只有生成的 woff2 放在 `public/` 或最终静态资源目录。

## 4. 字体使用映射

### 4.1 错误结构

```js
const sections = {
    SectionA: {
        text: allTextInSectionA,
        fonts: ['fontA', 'fontB', 'fontC'],
    },
}
```

如果遍历这个结构，很容易得到：

```text
SectionA 全部文字 → fontA
SectionA 全部文字 → fontB
SectionA 全部文字 → fontC
```

这会严重扩大字体子集。

### 4.2 正确结构

```js
const sections = {
    SectionA: {
        fonts: {
            fontA: [
                '实际由 fontA 显示的标题',
                '实际由 fontA 显示的正文',
            ],
            fontB: [
                '实际由 fontB 显示的按钮文字',
            ],
        },
    },
}
```

每一种字体只读取自己的文字数组。

### 4.3 共享区域

Header 应单独处理：

```js
const headerFont = {
    sourceFont: 'fontA',
    alias: 'FontA-Header',
    texts: ['站名'],
}
```

如果 Header 其他文字使用系统字体，则不能把它们加入 Header Web Font 字表，也不能将 Header 根节点设置成该 Web Font。

## 5. 字符集合生成

```js
function charactersFrom(text) {
    return [...new Set(
        [...text].filter((character) => !/\s/.test(character))
    )].sort().join('')
}
```

处理步骤：

1. 合并同一字体使用点的所有文字。
2. 按 Unicode code point 拆分字符串。
3. 去除空白字符。
4. 去重。
5. 排序，保证生成结果稳定。
6. 写出可审查的 txt 字表。

是否保留空格取决于生成工具。许多子集工具会自动处理基本空白，但应根据实际字体和工具版本验证。

不能用正则从完整 `.astro` 文件中提取所有文字，因为其中会包含：

- CSS 属性名
- 注释
- JavaScript 代码
- 备用字符串
- 不会显示的内容

更可靠的来源依次是：

1. 经过确认的数据字段。
2. 已确认的固定 UI 文案。
3. 经过审查的组件文字映射表。

## 6. glyphhanger 调用

glyphhanger 需要 URL 或 whitelist。对本地字表，应该传入 whitelist：

```js
execFileSync('pnpm', [
    'exec',
    'glyphhanger',
    `--whitelist=${characters}`,
    `--subset=${sourceFontPath}`,
    '--formats=woff2',
    `--output=${outputDirectory}`,
])
```

不要把本地 txt 路径作为第一个普通参数：

```bash
glyphhanger ./font/section.txt --subset=./font/source.ttf
```

否则 glyphhanger 可能将其解释为 URL 并尝试通过 HTTP 访问，结果没有真正使用预期的中文字表。

生成后必须检查：

- glyphhanger 输出是否包含中文 Unicode 范围
- woff2 文件是否存在
- 文件是否能由浏览器加载
- 生成大小是否符合文字数量预期

## 7. 内容 hash 文件名

```js
function hashFile(path) {
    return createHash('sha256')
        .update(readFileSync(path))
        .digest('hex')
        .slice(0, 8)
}
```

输出：

```text
<font>-<area>-<hash8>.woff2
```

内容 hash 的优点：

- 内容不变时 URL 不变
- 内容变化时 URL 自动变化
- 不需要手工维护版本号
- 可以安全使用 immutable 缓存

不推荐时间后缀或手动版本号，因为很容易出现：

```text
内容变化但忘记修改版本号 → 浏览器继续使用旧文件
内容不变但时间变化       → 产生无意义的新文件
```

## 8. 生成 CSS

每个生成文件对应一个独立 @font-face：

```css
@font-face {
    font-family: 'Huiwen-SectionA';
    src: url('/font/huiwen-section-a-1234abcd.woff2') format('woff2');
    font-weight: normal;
    font-style: normal;
    font-display: swap;
}
```

CSS 中的 alias 必须与组件实际使用的 family 完全一致。

生成 CSS 可以在页面初始化时声明。声明 @font-face 不等于一定会下载字体；浏览器通常会在某个元素实际使用该 family 时请求资源。

但如果要求真正按区域懒加载，还必须保证未激活区域没有引用对应 alias。

## 9. manifest

推荐 manifest 记录：

```ts
export const sectionFontManifest = {
    SectionA: [
        {
            alias: 'Huiwen-SectionA',
            url: '/font/huiwen-section-a-1234abcd.woff2',
            sample: '实际文字样本',
        },
    ],
    SectionB: [],
} as const
```

字段含义：

- `alias`：运行时 CSS 和 Font Loading API 使用的 family
- `url`：实际 hash 资源 URL
- `sample`：调用 `document.fonts.load()` 时使用的文字

共享 Header 不应放进分页 section manifest：

```text
Header → Header 自己的 CSS
SectionA/SectionB → sectionFontManifest
```

## 10. 共享 Header 加载

Header 组件自身引入 Header 字体 CSS：

```astro
import './header.css'
import '@/css/generated-header-font.css'
```

Header 根节点使用系统字体：

```css
header[data-header] {
    font-family: system-ui, sans-serif;
}
```

只有站名单独使用 Web Font：

```css
.title-text {
    font-family: 'Huiwen-Header', system-ui, sans-serif;
}
```

这样 Header 的其他文字不会被意外加入 Web Font 请求。

## 11. 当前 section 的字体加载

如果当前页面的 CSS 已经正确使用 alias，可以由 CSS 自然触发加载。

如果需要在页面显示前主动准备：

```ts
for (const { alias, sample } of manifest[section]) {
    document.fonts.load(`1em "${alias}"`, sample)
}
```

这里使用 alias，而不是原始 family：

```ts
document.fonts.load('1em "Huiwen"', sample)
```

不能代替：

```ts
document.fonts.load('1em "Huiwen-SectionA"', sample)
```

否则可能检查或加载了错误的字体。

不建议同时使用 CSS @font-face 和独立 `new FontFace()` 注册同一字体，除非明确知道两套注册路径的缓存和生命周期行为。

## 12. 分页状态

推荐使用两个状态：

```text
is-active
    当前稳定显示的区域

is-entering
    正在进入、已经开始参与过渡的区域
```

翻页开始：

```text
旧区域继续保留 is-active
新区域添加 is-entering
准备新区域字体
启动过渡
```

翻页完成：

```text
隐藏旧区域
旧区域移除 is-active
新区域移除 is-entering
新区域添加 is-active
```

字体 CSS 同时覆盖两个状态：

```css
#SectionA.is-active .title,
#SectionA.is-entering .title {
    font-family: 'Font-SectionA', system-ui, sans-serif;
}
```

关键规则：

```text
旧区域在离开动画完成前不能失去字体引用
```

否则旧区域还可见时会突然变成 fallback。

## 13. 全并行后台预取

预取器只负责非当前区域：

```ts
const active = currentSection()
const futureFonts = Object.entries(sectionFontManifest)
    .filter(([section]) => section !== active)
    .flatMap(([, entries]) => entries)
```

使用动态 preload：

```ts
const link = document.createElement('link')
link.rel = 'preload'
link.as = 'font'
link.type = 'font/woff2'
link.crossOrigin = 'anonymous'
link.setAttribute('fetchpriority', 'low')
link.href = url
document.head.appendChild(link)
```

注意：

- preload 只负责取得资源，不负责注册 CSS family
- `crossorigin` 必须与字体请求模式匹配
- URL 必须与 @font-face 中的 URL 完全一致
- 低优先级和延迟时机用于避免抢占首屏资源
- 必须用 URL 去重

推荐时机：

```text
当前区域初始化
→ 首屏进入稳定状态
→ requestIdleCallback
→ 不支持时使用 setTimeout fallback
→ 其余资源一次性并行预取
```

如果用户打开 Save-Data，可以跳过后台预取：

```ts
if (navigator.connection?.saveData) return
```

## 14. 缓存和部署

hash 文件适合：

```http
Cache-Control: public, max-age=31536000, immutable
```

服务器必须确认：

- URL 路径指向实际静态字体目录
- `Content-Type` 为 `font/woff2`
- 代理不会把字体请求转发到错误的 SSR 路径
- gzip/brotli 不需要重复处理已经压缩的 woff2

## 15. 常见问题排查

### 请求不存在

检查：

- 生成文件是否存在
- manifest URL 是否正确
- CSS URL 是否正确
- 服务器静态目录是否映射
- 是否在生成文件前启动了开发服务器

### 请求 200 但字体没有使用

检查：

```js
getComputedStyle(element).fontFamily
```

如果 computed style 没有目标 alias，是 CSS selector 或激活状态问题。

### computed style 正确但视觉仍像系统字体

检查：

- 目标字是否存在于子集 cmap
- 目标字体是否覆盖该文字
- 浏览器是否对缺失 glyph 做了逐字 fallback
- 生成字表是否漏字

### 只在翻页时闪烁

检查：

- 旧区域是否在动画开始时被移除了 active
- 新区域是否太晚才进入字体规则
- 是否错误地等待 `document.fonts.ready`
- 是否发生了字体 alias 切换

## 16. 可复用实施顺序

1. 盘点所有现有 font-family 使用点。
2. 明确每个使用点的真实文字来源。
3. 把共享区域和分页区域分开。
4. 建立字体使用映射。
5. 生成字表并审查字符数量。
6. 调 glyphhanger 生成 woff2。
7. 计算 hash 并生成 CSS/manifest。
8. 迁移 CSS 和 JS 到 alias。
9. 加入 active/entering 状态。
10. 加入当前页字体准备。
11. 加入其他页面字体全并行预取。
12. 配置缓存。
13. 构建和浏览器验证。

## 17. 验收标准

- 每个字体子集的字表与实际使用点对应
- 不相关文字没有被打进字体
- Header 与分页 manifest 分离
- 当前页字体优先可用
- 其他字体后台并行预取
- 翻页期间旧页不闪烁
- 直接 URL 入口可用
- 字体加载失败时有系统 fallback
- 资源更新后 hash 自动变化
- 浏览器可以复用长期缓存
- 没有重复注册或重复请求
